# PR 설명 초안

## 프롬프트

```
현재 브랜치와 develop의 차이를 보고 PR 설명을 작성해줘.

git diff origin/develop...HEAD 와 git log origin/develop..HEAD 를 먼저 읽어.

형식은 .github/pull_request_template.md 를 따르되:
- "변경사항"은 한두 줄. 파일 나열이 아니라 의도를 쓸 것
- "검증 결과"는 내가 실제로 돌린 명령을 쓸 것. 추측해서 채우지 말고,
  모르면 나에게 물어봐
- "사전 예측"은 작업 시작 시 남긴 기록을 사용할 것. 없으면 사후에 추정해서 채우지 말고 나에게 물어봐
- "실제 결과·트러블슈팅"은 실제 소요·결과, 병목·해결 과정, 배운 점·후속 작업을 각각 한 줄로 쓸 것
- 담당 주 영역, API Contract 양쪽 반영 여부, 시크릿 포함 여부는 확인한 사실만 쓸 것
- 체크리스트는 채우지 마. 내가 직접 확인하고 체크한다

한국어 '습니다' 체로 쓰고, 커밋 메시지를 그대로 복사하지 마.
```

## 왜 이렇게 쓰나

체크리스트를 AI가 채우면 검토 자체가 형해화된다. 확인은 사람이 한다.
